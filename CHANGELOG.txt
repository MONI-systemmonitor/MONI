[1.1.1] - the update that could not find itself

  A patch, because nothing was added to MONI.
  Two faults were cured, and both were in the
  updater 1.1.0 introduced.

  * 1.1.0 COULD NOT SEE ITS OWN RELEASE, AND SO IT
    COULD NEVER HAVE UPDATED ITSELF - not to this
    version and not to any version after it. It
    asked for a file named MONI-setup.exe in the
    newest release, and the release of 1.1.0 carried
    a file named MONI-1.1.0-setup.exe. The address
    it asked answered "page not found". If you are
    on 1.1.0, download this version by hand from the
    release page once: from here on the button
    works.

  * AND THE INSTALL BUTTON IN SETTINGS DID NOTHING
    ON 1.1.0. It asks the release page what the
    newest installer is called and what it hashes
    to, and it was looking for a name with the
    version inside it. The release page answered
    with a file it did not recognise, so MONI
    decided no installer existed and did nothing at
    all. It now recognises the file whatever the
    name is, so this cannot happen again if the
    name is ever changed back.

  * Nothing else changes. The installer already
    started MONI again after a silent install, and
    it still does; your boards, your settings and
    your notifications are untouched by any of it.

[1.1.0] - MONI updates itself

  Two things the program now does that it never
  did before: it looks for a newer version when it
  starts, and it installs one when you say so.
  Nothing else about MONI changes, and the check
  can be turned off.

  * MONI LOOKS FOR A NEWER VERSION WHEN IT STARTS.
    It asks the same one address the Check for
    updates button asks, ONCE, and only after the
    board is up - so nothing about the start is
    slower. If there is a newer version it says so
    in the notification center and on the status
    bar. If there is not, it says NOTHING AT ALL:
    a message on every launch saying nothing has
    happened is noise, and noise is what makes
    people turn a feature off. If there is no
    network it also says nothing, because a machine
    with no internet is not a fault - the reason
    goes in MONI's log, where a fault is looked for.
    There is a tick box in Settings, under Starting
    up, to turn it off.

  * AND IT CAN INSTALL THE NEW VERSION FOR YOU.
    Settings, under About, now has a second button
    beside Check for updates: it downloads the
    installer, CHECKS THAT IT ARRIVED WHOLE, closes
    MONI, runs the installer without showing you a
    wizard, and starts MONI again. The release page
    is still offered beside it for anybody who would
    rather do it by hand.

  * THE ORDER IS THE DESIGN, AND IT IS THE PART TO
    TRUST. Nothing on your machine is replaced until
    the file has been downloaded and checked: the
    download goes to a temporary file, its size is
    compared with what the server said, and its
    SHA-256 is compared with the hash the release
    page records. A download that failed, arrived
    truncated, or does not match is STOPPED - MONI
    says so on screen, keeps working, and your
    installation is exactly as it was. A
    half-replaced MONI is worse than an old one.

  * MONI SAYS WHAT IT IS DOING WHILE IT DOES IT.
    A small window names each step - asking,
    downloading, checking, closing - because a
    program that vanishes and comes back with no
    explanation is alarming even when it worked.

  * The check itself is unchanged, and so is the
    address it asks. MONI still does not touch the
    network unless you have asked it to: the launch
    check is one request, and everything else waits
    for a press.

[1.0.4] - the uninstaller leaves nothing behind

  * UNINSTALLING LEFT AN EMPTY-LOOKING FOLDER AND ONE
    FILE IN IT: uninstall-startup-entry.txt, a report
    the installer's own tidying-up writes into the
    folder MONI was installed in while it works.
    Windows does not delete a folder while anything is
    inside it, so that one file kept the whole folder
    standing after MONI had been removed. The folder
    now goes with everything in it, whatever put it
    there.
  * CHECK FOR UPDATES NOW TAKES YOU TO THE NEW
    VERSION. When there is a newer one, Settings ->
    About opens the release page in your browser so
    you can download it. Until now the answer named
    the address and stopped there, which is a dead
    end for anyone who does not want to copy a URL by
    hand. MONI still never installs anything itself:
    the page opens, and you decide.

[1.0.3] - the installer's "Run MONI" box now works

  Found by ticking it for the first time, which nobody
  ever had.

  * THE INSTALLER'S OWN "RUN MONI NOW" CHECK BOX DID
    NOTHING BUT SHOW AN ERROR. It read "Unable to
    execute file: MONI.exe - CreateProcess failed;
    code 740. The requested operation requires
    elevation." MONI asks Windows
    for administrator rights, and the installer was
    starting it in a way that does not read that
    request, so Windows refused it outright. The
    installer now hands the launch to Windows the same
    way the Start menu shortcut does, which reads it
    and starts MONI with the rights it needs. The
    program was always installed correctly - only this
    one check box was broken.
  * The version file MONI ships beside itself, which
    the update check reads, said 1.0.1 in the previous
    build while the program said 1.0.2. It now moves
    with the version.

[1.0.2] - the two things using 1.0.1 found

  A patch again: nothing was added to the program.

  * THE "START MONI WHEN WINDOWS STARTS" BOX COULD
    NOT BE CLICKED. On any machine whose Windows
    security settings are at their default - which is
    almost every machine - the box was greyed out and
    the setting could not be reached at all. The rule
    behind that was written for the old kind of startup
    entry, which Windows genuinely cannot use to start
    an administrator program; the entry MONI writes now
    is a scheduled task, which needs no permission from
    anybody. The rule is gone, the box works, and the
    sentence under it says what will actually happen
    instead of saying MONI refuses.
  * THE HIDE / SHOW BUTTON NOW SAYS WHAT IT DOES. It
    was a bare arrow, because words wide enough to read
    reached over a tile. It reads Hide bars / Show bars
    and stands in the strip of margin a tile keeps above
    itself, which is the one place on a full board that
    holds no control of any tile. It is still there in
    fullscreen and while both bars are hidden, and it
    still costs the board nothing.

[1.0.1] - the first build with two faults cured

  A patch rather than a feature release: nothing was
  added to the program. A published 1.0.1 against an
  installed 1.0.0 is also what makes the update check
  show its "a newer version is available" message - the
  half of that feature nobody had seen, because until
  now the version file and the built program said the
  same number.

  * AN UPGRADE NO LONGER LEAVES A STARTUP ENTRY BEHIND
    THAT POINTS AT A PROGRAM IT DELETED. MONI 1.0.0
    wrote its startup entry under a name, and the build
    that replaced it in the same folder was called
    something else - so a machine that was upgraded kept
    an entry naming a file that was no longer there.
    That entry is now swept away when MONI starts, and
    by the installer as it installs, so a machine that
    has just been upgraded is clean before MONI is ever
    run. Nothing needs doing by hand and Settings does
    not have to be opened.
  * THE WAY BACK FROM THE HIDDEN BARS IS A FLOATING
    BUTTON, not a third bar. Hiding the toolbar and the
    status bar is done to give the board their height,
    and the button that brings them back now costs the
    board nothing at all: it sits over the board's own
    corner, it is still there in fullscreen and with
    both bars hidden, and it never covers a tile.

[1.0.0] - the first working version

  MONI 1.0.0 is the first WORKING version of MONI -
  the earlier attempts never came close to this one,
  so this is v1.0 rather than a third attempt at a
  program nobody used. The version is read out of
  MONI.exe itself, so this heading and the number
  on the About section cannot disagree. What is in
  it:

  * The board writes itself: a change is saved a moment
    after it is made, and closing MONI saves as well, so
    a board survives a crash or a forced close. The
    status bar says when it was last written - Saved,
    Saved just now, Saved 4 minutes ago.
  * About section in Settings: this file, the version,
    and where updates are checked. It is collapsed to
    begin with.
  * The version is read out of MONI.exe itself, so it
    cannot disagree with the build that is running.
  * The installer and the uninstaller: MONI lands in
    Program Files, and the sensor driver is taken off
    the machine when MONI is removed.
  * The updater asks one short text file which version
    is current, compares it with this build, and prints
    the address of the download page when a newer one
    exists. It never replaces MONI itself, and nothing
    is downloaded or started on its own.
  * One version number, written once in MONI.csproj:
    the About section, the installer and the updater
    all read that one number, so they cannot disagree
    about which build this is.

  The driver: MONI.sys (WinRing0) is what reads the
  processor temperature, the fans and the storage
  hardware, and it is why MONI asks for administrator
  rights. It is a kernel service, registered as R0MONI,
  rather than a copied file, and the first elevated run
  of MONI registers it.
